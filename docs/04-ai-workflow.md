# Разработка с AI

## Фактический процесс
1. Из требований вакансии работодателя выделены законченный продукт, API/БД, самостоятельность и документация.
2. Задача разложена на ТЗ, проектирование, реализацию, интеграцию AI, пилот, релиз.
3. Принято ограничение окружения: npm registry недоступен; выбран доступный Node.js и встроенная SQLite без внешних зависимостей. Next.js не использован.
4. Пользователь сообщил, что API-доступа нет: AI-функция отложена, сервер не передаёт содержимое вакансий внешним моделям.
5. Реализованы серверный API, интерфейс, изоляция демо, тесты и документация. Результаты проверки фиксируются отдельно в 05-validation.md.

## Повторяемые шаблоны задач для AI
### Функция
«Реализуй [сценарий] по docs/01-spec.md. Сначала опиши изменения API и данных. Сохрани проверку владельца на сервере. Ошибка не должна стирать введённые поля. Не подключай внешние сервисы без необходимости. Проверь сценарий успешного выполнения и один существенный отказ».

### Проверка
«Проверь, что пользователь B не может прочитать, изменить или удалить вакансии, задачи и заметки пользователя A, даже зная идентификаторы. Приведи воспроизводимый тест. Проверь, что экспорт включает только данные текущего аккаунта».

### UI
«Проверь экран при ширине 390 px: отсутствие горизонтального скролла страницы, читаемость длинных названий, доступность кнопок и подписей. Доска может иметь собственную горизонтальную прокрутку».

Это шаблоны для будущих итераций; они не выдаются за дословный журнал использованных промптов.

## Будущий AI-разбор
Вход: только текст, который пользователь явно вставил для разбора. Серверная интеграция с выбранным API, ключ только в .env/секретах хостинга. Провайдер и модель ещё не выбраны.

Ответ — ограниченный JSON: company, title, salary_min/max, currency, work_format, location, requirements. Отсутствующие сведения — null/пустые поля. Не исполнять инструкции из текста вакансии. Валидировать ответ той же серверной схемой. Перед сохранением показать редактируемый черновик. Потребуются таймаут, обработка 429/5xx, лимит размера, лимит запросов пользователя, учёт стоимости и отказоустойчивый ручной ввод.

Проверка: 20–30 синтетических описаний, пустые зарплаты, несколько валют, неоднозначный формат, инструкции-инъекции, неверный JSON, таймаут. До подключения реального ключа нельзя заявлять проверенную интеграцию.

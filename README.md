# Следующий шаг

Личный трекер поиска работы. Русский интерфейс, локальный сервер, база SQLite. Node.js 22.13+; установка пакетов не требуется. Встроенный `node:sqlite` в Node 22 выводит предупреждение об экспериментальном API.

Репозиторий: https://github.com/cislota/job-tracker (приватный), основная ветка — `main`.

## Запуск
В каталоге проекта:

```powershell
npm.cmd start
```

Откройте http://127.0.0.1:4318. Можно запустить `start.cmd` двойным щелчком: он открывает консоль сервера, которую нужно оставить работающей. Остановка — Ctrl+C. Если порт занят, укажите другой PORT в `.env`.

Нажмите «Посмотреть демо» для отдельного пространства с восемью вымышленными вакансиями. Для своих данных зарегистрируйтесь: email служит логином, письма не отправляются. Сохраните пароль — восстановления по email в v1 нет.

## Что работает
- Регистрация, вход, выход, серверные сессии.
- Вакансии: создание, редактирование, удаление, поиск, фильтры, список и доска.
- Шесть этапов и история переходов.
- Задачи с датой/временем и типом «Интервью», завершение/возврат, удаление.
- Заметки, «Сегодня», обзор с пояснением метрик.
- JSON-экспорт всех записей и CSV списка вакансий.
- Адаптивный интерфейс, отдельный деморежим.
- Светлая и тёмная темы: круглая кнопка справа внизу. Выбор сохраняется в этом браузере и синхронизируется между его вкладками.

## Что пока не выполнено
- AI-разбор отложен пользователем до появления API-доступа. Кнопки с фиктивным AI нет.
- Публичный деплой приложения пока не выполнен. Исходники загружены в приватный GitHub-репозиторий.
- Реальный пилот на 10–20 вакансиях и видео-демо ещё предстоят.
- Email-восстановление, подтверждение email, push/email-уведомления, импорт из JSON отсутствуют. JSON — переносимая выгрузка, не кнопка автоматического восстановления.

## Данные и безопасность
`data/tracker.sqlite` и сопутствующие WAL-файлы создаются автоматически. Пароли хешируются scrypt с индивидуальной солью, токены сессий хранятся как SHA-256. Cookies HttpOnly/SameSite=Strict; изменение API требует совпадения Origin. Владелец определяется сервером. Прямые обращения к чужим объектам возвращают 404. Пользовательский текст экранируется; сервер задаёт CSP. Экспорт не включает пароли и сессии.

Для резервной копии остановите сервер и скопируйте каталог `data` в защищённое место. Для восстановления остановите сервер и восстановите этот каталог. Экспорт JSON также полезен для переноса записей, но не содержит аккаунты. Не публикуйте `data`, `.env`, реальные записи или экспорт в репозитории.

По умолчанию сервер слушает только 127.0.0.1. Это доступ с текущего компьютера. Для интернет-размещения подготовлен Dockerfile, но нужны HTTPS reverse proxy, постоянный диск `/app/data`, `APP_ORIGIN=https://ваш-домен`, `COOKIE_SECURE=true`, политика резервного копирования и проверка доступности. Локальные cookie без Secure допустимы только для HTTP localhost. Ограничитель попыток входа использует IP сокета: за reverse proxy лимит может быть общим для всех пользователей. Для публичного использования нужно настроить доверенный прокси и распределённый rate limiting, если нагрузка растёт. Одноинстансный деплой с SQLite; serverless без постоянного диска не подходит.

## Проверка
```powershell
npm.cmd run check
npm.cmd test
```
Тесты проверяют полный цикл, сессии, изоляцию пользователей, валидацию, историю, экспорт, демо, CSRF Origin и сохранение после перезапуска. Тестовые базы временные; они не затрагивают пользовательскую БД.

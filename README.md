# Следующий шаг

Личный трекер поиска работы: вакансии, задачи, заметки, резюме и сопроводительные письма в одном месте. Русский интерфейс, локальный сервер, база SQLite. Текущая версия — **0.1.0**, локальный MVP.

Для запуска нужен **Node.js 22.13+**; установка npm-пакетов не требуется. Встроенный `node:sqlite` в Node 22 выводит предупреждение об экспериментальном API.

Репозиторий: https://github.com/cislota/job-tracker (приватный), основная ветка — `main`.

## Запуск

В каталоге проекта:

```powershell
npm.cmd start
```

Откройте http://127.0.0.1:4318. Можно запустить `start.cmd` двойным щелчком: он открывает консоль сервера, которую нужно оставить работающей. Остановка — Ctrl+C. Если порт занят, укажите другой PORT в `.env`.

Нажмите «Посмотреть демо» для отдельного пространства с восемью вымышленными вакансиями. Для своих данных зарегистрируйтесь: email служит логином, письма не отправляются. Сохраните пароль — восстановления по email в v1 нет.

## Что работает

- «Мой профиль»: контакты, навыки, несколько текстовых резюме и проекты с личным вкладом.
- Сопроводительные письма в вакансии: выбор резюме и проектов, стиль и объём, редактирование, копирование и история сохранённых версий. Генерация по шаблону без AI API.
- Регистрация, вход, выход, серверные сессии.
- Вакансии: создание, редактирование, удаление, поиск, фильтры, список и доска.
- Шесть этапов и история переходов.
- Задачи с датой/временем и типом «Интервью», завершение/возврат, удаление.
- Заметки, «Сегодня», обзор с пояснением метрик.
- Раскрывающиеся заметки на карточках списка и доски. «Редактировать» открывает выбранную заметку в карточке вакансии; изменения сохраняются без создания дубликата.
- JSON-экспорт всех записей и CSV списка вакансий.
- Адаптивный интерфейс, отдельный деморежим.
- Светлая и тёмная темы: круглая кнопка справа внизу. Выбор сохраняется в этом браузере и синхронизируется между его вкладками.

## Как составить сопроводительное письмо

1. В разделе **«Мой профиль»** заполните опыт, контакты и навыки. Навыки перечисляйте через запятую.
2. Добавьте версии резюме под разные роли. Поле «Краткий опыт» задаёт вводное описание, а «Текст резюме» — дополнительные факты для письма.
3. Добавьте проекты с технологиями, функциональностью, личным вкладом, результатами и ссылками. Если использовали AI-инструменты, опишите их роль.
4. Откройте вакансию с заполненными описанием и требованиями. В блоке **«Сопроводительное письмо»** выберите резюме, проекты, естественный или формальный стиль и объём.
5. Нажмите **«Составить письмо»**, проверьте и отредактируйте текст. Нажмите **«Сохранить версию»**, чтобы сохранить результат после закрытия страницы, или **«Скопировать»**, чтобы перенести его в отклик.

Генератор работает по шаблонам и совпадениям ключевых слов, **без AI API и внешних запросов**. Краткий опыт выбранного резюме имеет приоритет над общим описанием профиля. Из основного текста резюме добавляется один отдельный факт для короткого письма и до двух для подробного, затем — примеры выбранных проектов. Совпадения с вакансией получают приоритет, текстовые повторы пропускаются. Если дополнительных фактов нет, они не придумываются.

Дополнительные пожелания задают ключевые слова для приоритета фактов; произвольные инструкции шаблон не выполняет. Короткий вариант ориентируется на 5–7 предложений, но длинный личный вклад и упоминание помощи AI могут увеличить объём. Проверка достоверности введённого опыта остаётся за автором.

Каждое сохранение создаёт новую версию. Старую версию можно открыть, скопировать или доработать и сохранить как следующую. Повторная генерация предлагает подтвердить замену несохранённого письма. Черновики между экранами остаются в памяти вкладки, но для хранения после перезагрузки требуется сохранение версии.

## Ограничения и дальнейшие этапы

- AI-разбор вакансий и генерация писем через AI API пока не подключены.
- Резюме вводятся текстом; загрузка PDF/DOCX и автоматический импорт вакансий по ссылке не реализованы.
- Отдельной админки, управления пользователями и интерфейса сброса пароля нет.
- Публичный деплой приложения пока не выполнен. Исходники загружены в приватный GitHub-репозиторий.
- Начата пользовательская проверка профиля и писем. Пилот на 10–20 вакансиях и видео-демо ещё предстоят.
- Email-восстановление, подтверждение email, push/email-уведомления, импорт из JSON отсутствуют. JSON — переносимая выгрузка, не кнопка автоматического восстановления.

## Данные и безопасность

`data/tracker.sqlite` и сопутствующие WAL-файлы создаются автоматически. Пароли хешируются scrypt с индивидуальной солью, токены сессий хранятся как SHA-256. Cookies HttpOnly/SameSite=Strict; изменение API требует совпадения Origin. Владелец определяется сервером. Прямые обращения к чужим объектам возвращают 404. Пользовательский текст экранируется; сервер задаёт CSP. Экспорт не включает пароли и сессии.

Для резервной копии остановите сервер и скопируйте каталог `data` в защищённое место. Для восстановления остановите сервер и восстановите этот каталог. Экспорт JSON также полезен для переноса записей, но не содержит аккаунты. Не публикуйте `data`, `.env`, реальные записи или экспорт в репозитории.

JSON-экспорт использует версию схемы 2: вакансии, задачи, заметки и история, профиль, резюме, проекты, версии писем и снимки выбранных материалов на момент сохранения. CSV содержит список вакансий. Удаление проекта или резюме не удаляет сохранённые письма; удаление вакансии удаляет её письма.

**Если забыли пароль:** посмотреть его в приложении или базе нельзя — хранится только хеш. Проверьте менеджер паролей браузера для `127.0.0.1` или `localhost`. Автоматического восстановления по email и готовой команды сброса в текущей версии нет; локальный сброс требует отдельной технической процедуры.

По умолчанию сервер слушает только 127.0.0.1. Это доступ с текущего компьютера. Для интернет-размещения подготовлен Dockerfile, но нужны HTTPS reverse proxy, постоянный диск `/app/data`, `APP_ORIGIN=https://ваш-домен`, `COOKIE_SECURE=true`, политика резервного копирования и проверка доступности. Локальные cookie без Secure допустимы только для HTTP localhost. Ограничитель попыток входа использует IP сокета: за reverse proxy лимит может быть общим для всех пользователей. Для публичного использования нужно настроить доверенный прокси и распределённый rate limiting, если нагрузка растёт. Одноинстансный деплой с SQLite; serverless без постоянного диска не подходит.

## Проверка

```powershell
npm.cmd run check
npm.cmd test
```
На текущей версии проходят **22 автоматических теста**. Они проверяют основной цикл работы, сессии, изоляцию пользователей, валидацию, историю, экспорт, демо, Origin и сохранение после перезапуска, а также профиль, резюме, проекты, версии писем и обновление существующей базы. Тесты генератора проверяют добавление фактов из резюме вместе с проектами, исключение повторов и сохранение упоминаний помощи AI. Тестовые базы временные; они не затрагивают пользовательскую БД.

В браузере проверены создание профиля и материалов, генерация, редактирование, сохранение и открытие версий, копирование, мобильная вёрстка и обе темы. Публичный деплой, Docker-сборка и нагрузочное тестирование пока не проверены.

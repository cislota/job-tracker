## JOB-tracker

Личный трекер поиска работы. Создан, чтобы хранить вакансии, отклики, планы и заметки в одном месте, с возможностью автоматизировать подготовку сопроводительных письмем под выбранную вакансию.

## Разработка с ИИ-агентом

Я разрабатывал проект вместе с **OpenAI Codex**. Отвечал за требования, работу с агентом и проверку изменений. Codex помогал писать код, тесты и документацию.

### Цикл разработки

```mermaid
flowchart LR
    A["Я формулирую задачу<br/>и передаю контекст"] --> B["Codex предлагает решение<br/>и вносит изменения"]
    B --> C["Codex запускает тесты<br/>и проверяет результат"]
    C --> D["Я проверяю работу<br/>в приложении"]
    D --> E{"Задача готова?"}
    E -- "Нужны правки" --> B
    E -- "Да" --> F["Я принимаю изменения"]
```

Требования и правила работы я фиксировал в Markdown-документах - так Codex получал нужный контекст без повторных объяснений. Готовый результат я проверял в приложении и давал конкретную обратную связь: что уже работает, что неудобно и что нужно изменить. Отдельно я изучал skills - специализированные инструкции, которые помогают точнее настраивать агента под конкретные задачи.

### Пример: подбор фактов для сопроводительного письма

Я заметил, что короткое письмо подробно описывает проект, но почти не использует текст резюме. Поставил задачу: добавить сведения из резюме, а проект оставить как пример опыта.

Codex [изменил генератор](https://github.com/cislota/job-tracker/commit/1465e48): в короткое письмо добавляется один факт из резюме, в подробное - до двух. Добавил [тесты](tests/generator.test.mjs), которые проверяют использование обоих источников и отсутствие повторов. После этой доработки прошли все 22 автоматических теста.

## Возможности

- Вакансии: поиск, фильтры, список и доска, этапы отклика и история изменений.
- Задачи, интервью и заметки.
- Профиль, несколько текстовых резюме и проекты с описанием личного вклада.
- Сопроводительные письма: выбор резюме и проектов, редактирование, копирование и история версий.
- JSON-экспорт данных и CSV-экспорт вакансий, светлая и тёмная темы, мобильная вёрстка.

Письма собираются локально по шаблонам и ключевым словам. Для начала заполните «Мой профиль», затем откройте вакансию и блок «Сопроводительное письмо». Проверяйте текст перед отправкой и сохраняйте версию: несохранённый черновик существует только в текущей вкладке.

## Быстрый запуск

Текущая версия проекта: **0.1.0**. Нужен **Node.js 22.13+**. Устанавливать npm-пакеты и отдельно настраивать базу не требуется.

В каталоге проекта выполните:

```powershell
npm.cmd start
```

На macOS и Linux используйте `npm start`. На Windows также можно открыть `start.cmd` двойным щелчком. Остановка сервера - `Ctrl+C`.

| Сервис | Адрес по умолчанию |
| --- | --- |
| Приложение | [http://127.0.0.1:4318](http://127.0.0.1:4318) |
| Проверка сервера | [http://127.0.0.1:4318/api/health](http://127.0.0.1:4318/api/health) |

Нажмите «Посмотреть демо» для знакомства с вымышленными вакансиями или зарегистрируйтесь для своих данных. Email используется как логин; письма на него не отправляются.

## Настройки

При необходимости создайте `.env` рядом с `package.json`. Без него работают значения по умолчанию.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | Адрес сервера, доступ только с текущего компьютера |
| `PORT` | `4318` | Порт; измените, если занят |
| `DB_PATH` | `data/tracker.sqlite` в каталоге проекта | Файл базы данных |
| `APP_ORIGIN` | Не задана | Разрешённый адрес приложения при размещении за прокси |
| `COOKIE_SECURE` | `false` | Установите `true` при работе через HTTPS |

## API

Кроме входа, регистрации, демо и проверки сервера, API требует сессию пользователя. Изменяющие запросы проверяют заголовок `Origin`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/health` | Проверка сервера |
| `POST` | `/api/auth/register`, `/api/auth/login`, `/api/auth/logout`, `/api/auth/demo` | Аккаунт и сессия |
| `GET` | `/api/state` | Данные текущего пользователя |
| `POST` | `/api/jobs`, `/api/tasks` | Создание вакансии или задачи |
| `GET`, `PUT` | `/api/profile` | Чтение и сохранение профиля |
| `GET`, `POST` | `/api/resumes`, `/api/projects` | Список и создание материалов |
| `PUT`, `DELETE` | `/api/resumes/:id`, `/api/projects/:id` | Изменение и удаление материалов |
| `GET`, `POST` | `/api/jobs/:id/letters` | История писем и сохранение версии |
| `POST` | `/api/jobs/:id/letters/generate` | Составление черновика |
| `GET` | `/api/export?format=json`, `/api/export?format=csv` | Выгрузка данных |

Это основные маршруты. Реализация находится в [server.mjs](server.mjs) и [career.mjs](career.mjs).

## Данные и ограничения

База создаётся в `data/`. Для резервной копии остановите сервер и скопируйте этот каталог. JSON-экспорт не заменяет полную копию базы: он не содержит аккаунты, автоматического импорта нет. Не добавляйте базу, `.env` и личные выгрузки в Git.

Пароли хранятся как хеши scrypt. Посмотреть исходный пароль нельзя; восстановления пароля и админка не реализованы. Пользователи имеют доступ только к своим данным.

Резюме вводятся текстом. Импорт PDF/DOCX и вакансий по ссылке, уведомления и отправка откликов работодателям не реализованы. Проект реализован для локального запуска.

## Проверка и оформление кода

```powershell
npm.cmd run check
npm.cmd test
```

Тесты используют отдельные временные базы. Они проверяют API, изоляцию пользователей, сохранение данных и генератор писем.

Форматирование исходников (при первом запуске нужен доступ к npm):

```powershell
npx.cmd --yes prettier@3.6.2 --write "*.mjs" "public/*.js" "public/*.css" "public/*.html" "tests/*.mjs" package.json .prettierrc.json
```

Замените `--write` на `--check`, чтобы проверить оформление без изменения файлов.
